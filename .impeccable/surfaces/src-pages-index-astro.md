# Accueil RGAA Studio

## Surface

Page vitrine du produit · mode Persuade · français.

## Visiteur et tâche

Auditeurs RGAA/WCAG indépendants et en agence, équipes d’accessibilité, et organisations qui évaluent leur outillage. Ils doivent comprendre rapidement ce que RGAA Studio est, voir le logiciel dans un contexte réel et pouvoir le découvrir ou rejoindre la release existante.

## Preuve et contenu

- Captures réelles de RGAA Studio sur le site public numera11y.fr dans `public/media/`.
- L’outil relie le dossier, les pages, les vues d’analyse, les suggestions, les décisions humaines et les preuves.
- RGAA et WCAG ; chaque audit utilise un seul référentiel, avec un niveau A/AA/AAA requis pour WCAG.
- Les analyses automatisées sont des pistes de revue. Elles ne remplacent pas la décision de conformité.
- CTA principal : « Découvrir l’application », qui ouvre la dernière release GitHub. CTA secondaire : explorer le parcours sur la page.

## Contraintes

- Nommer le produit RGAA Studio. Garder numera11y en attribution discrète ; ne pas appliquer le logo numera11y comme marque principale.
- Ne pas inventer de clients, témoignages, scores, tarifs, conformité ou capacité qui n’existe pas.
- Distinguer démonstration illustrative et données de conformité réelles. Aucune décision humaine n’est enregistrée dans les captures.
- Préserver les usages clavier, le contraste, le mouvement réduit, la mise en page responsive et la lisibilité des captures.
- Déploiement visé : GitHub Pages. Domaine personnalisé à choisir.

## Direction contract

### THESIS

La page raconte un audit comme un fil traçable, de la page observée aux preuves. Elle refuse l’inventaire standard de fonctions dans des cartes jumelles.

### OWN-WORLD

RGAA Studio reste reconnaissable par son icône « R », son encre bleu nuit, son bleu d’action et ses surfaces claires bleu-lavande et crème. Une ligne de parcours construite en SVG relie les étapes ; les captures réelles du produit font preuve, pas décoration. Numera11y reste une attribution discrète.

### STORY

Les visiteurs voient le parcours dossier → page → repères → décision → preuve, comprennent que l’automatisation suggère et que l’auditeur décide, puis ouvrent la dernière release GitHub pour découvrir l’application.

### FIRST VIEWPORT

La barre de marque et de navigation ouvre sur un titre explicite et le parcours d’audit vivant. Une station montre la capture réelle de l’application ; les autres révèlent leurs étapes par activation. « Découvrir l’application » ouvre la dernière release GitHub ; le parcours interactif reste accessible comme action secondaire.
